# Implementation review, 17 October 2026

The implementation closes the main leakage and alignment risks from the design review. Two evaluator corrections should land before selection and confirmation. Neither requires retraining the reference or encoder. This review covers `model_common.py`, `neural.py`, `evaluate.py`, and the protocol as inspected before those corrections; root is separately extending cost/bootstrap reporting.

1. **Use unrounded values for adoption decisions.** `evaluate.confirm` tests the output of `harness.eval.paired`, which rounds each system's absolute accuracy before subtracting and rounds interval endpoints. The +1 percentage-point rule can therefore pass a smaller gain. With the actual confirmation size of 3,030 rows, synthetic counts of 278 versus 308 correct give an exact gain of .00990099, while `paired` reports .0100. Use direct full-precision accuracy differences and full-precision bootstrap quantiles for decisions; round only the displayed report. Apply the same principle to the intent margin. This is a synthetic numerical reproduction, not a confirmation result.

2. **Optimize thresholds for the routing objective actually executed.** `fit_correctness` currently charges review/error costs for every calibration row, while `Triage._finish` necessarily reviews some rows because of gate flags, inferred off-policy status, policy rules, or the fixed permission-support guard. Those rows should contribute a constant review cost, independent of the threshold. Including them in the threshold search can move the selected threshold and increase cost on rows that remain eligible for automatic handling. Obtain the mandatory-review mask with thresholds set to zero and the same OOF correctness scores, then search thresholds only over eligible rows. Match the service's six-decimal rounding of confidence before its strict `< threshold` comparison. Fit the final correctness regression as before; neural and classical weights need no changes. Untouched confirmation would still measure the old procedure honestly, but it would not be the stated service-cost optimization.

3. **Keep diagnostic claims within the implemented metrics.** `score_rows` currently assigns `_group="clean"` even for the noisy partition, and returns only a row count for hostile inputs. Separate per-split results do not compute the official combined top-70 ratio, clean-to-noisy gap, schema coverage, or all development bars. Run the official grader on the joined frozen dev/noisy/hostile predictions before claiming those bars, or explicitly leave them pending. The current confirmation accuracy metrics can still be used after item 1. Operational cost and paired routing intervals were not yet implemented in the inspected version and remain required by the protocol.

Checked behavior:

- Shared input construction is `gate.clean(project(row))`. The training targets remain separate from encoder text/state features. State normalization uses fitting rows only. The internal intent softmax is fixed at temperature 1; exported temperature calibration cannot alter action logits.
- The split contains 12,999 fitting, 2,014 selection, 1,957 calibration, and 3,030 confirmation rows. Conversation-disjointness assertions passed, and row IDs were unique within every partition. This check inspected membership/counts, not confirmation outcomes.
- Reference preparation stores a fitting-only intent-to-flow map. Neural output IDs and all three class axes are checked. Length-bucketed predictions scatter back to source-row offsets. The tokenizer wrapper uses the supported callable interface.
- Raw action and flow probabilities share one action blend weight; intent has its own selection weight. The policy prior is applied once, followed by the observed-action mask. Four fitting rows with synthetic probabilities produced exactly the same actions through `final_action_probs` and the real cached `Triage` path.
- Weight ties favor the first descending entry, hence the more classical option. The weights are *classical* weights: `action_weight=1` leaves reference actions unchanged, while 0 selects encoder action/flow probabilities. Both weights equal to 1 yield the reference. An intent-only change cannot satisfy the action-gain rule.
- Returning uniform probabilities for the secondary-intent probe does not change decisions under the explicitly fixed `route_second_intent=False`, LLM-off configuration. This adapter is unsuitable for claiming behavior under another configuration.
- The primary contrast is explicitly the frozen selected ensemble against the same-fit reference. Standalone encoder results are descriptive. Calibration correctness scores remain only partially OOF because upstream temperature fits are shared, as disclosed. No current-round confirmation-label use in model fitting or candidate selection was found.

This was a static review plus small local synthetic checks. No heavy computation, training, provider request, confirmation prediction, or confirmation score was run. Cached replay validates the decision path; it does not establish encoder serving latency, memory use, or production integration.
