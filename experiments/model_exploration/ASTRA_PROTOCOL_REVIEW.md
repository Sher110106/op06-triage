# Pre-execution protocol review, 17 October 2026

The proposed four-way conversation split supports a useful current-round comparison. Proceed after clarifying the inference graph, shared policy behavior, and confirmation scope below. None requires another training run or a new administrative gate.

This review covers the design supplied to the reviewer and existing `triage/classical.py`, `triage/data.py`, `triage/text.py`, `triage/pipeline.py`, `data/op06/grader.py`, and the refinement experiment. The new protocol and implementation were not yet present during the initial inspection. This is a design review, not a claim that the forthcoming code has passed review or that any model has improved accuracy. No training, API call, or confirmation evaluation was run.

1. **Keep the neural action head's internal intent input fixed.** Joint training with a predicted intent softmax is valid; it must never receive the gold intent vector. Keep that internal softmax at the same temperature used during training, normally 1. Apply learned temperatures to exported intent/flow/action logits outside the neural forward graph. Replacing the action head's intent input with calibrated probabilities after training changes its inputs and invalidates cached action logits and independently fitted action temperatures. The smallest implementation check is that changing only the exported intent temperature leaves the neural raw action logits unchanged. Gold fields must be removed before text and state construction.

2. **Define calibration OOF claims narrowly.** Grouped OOF correctness fits exclude each scored conversation from the correctness regression, but temperatures are fitted using all calibration labels. Further, the selected ensemble weight depends on these temperatures. Therefore those OOF scores are not an unbiased estimate of the entire calibrated pipeline. Untouched confirmation still gives a valid current-round check of the frozen procedure. The minimal correction is to state this limitation and reserve calibration results for fitting thresholds. Fully cross-fitting temperatures and the dependent selection procedure is only necessary if claiming unbiased calibration-set performance. Do not spend another split or large training run merely to produce that claim.

3. **Freeze the exact policy and input path for both systems.** The existing production path runs `gate.clean`, applies a policy prior, applies observed-action masks, computes correctness confidence on the resulting probabilities, and adds routing reasons including the .90 permission-support guard. The old refinement helper omits several of those steps. Either implement these shared steps for both new systems, or call the result an offline model comparison and defer service claims until integration. Specify whether the mix coefficient is shared by all three heads, freeze tie-breaking, and apply exactly one prior using the chosen mixed flow probabilities. Keep the existing guard fixed rather than adding a second guard search. Temperatures, confidence features, threshold fitting, and reported predictions must refer to the same final action distribution.

4. **Close the existing full-train lookup before a service comparison.** `pipeline.intent_flows` reads the whole training file when the bundle lacks `intent_flow`. Save the map from fitting rows in each experiment bundle, or use a documented fixed taxonomy independent of this round's labels. The same rule applies to permission tables and retrieval examples. Verify matching class names/order for every probability array and policy matrix; never silently drop a confirmation row whose label was absent from fit. Use a fixed ontology or count an unseen class as unsupported and wrong.

5. **Use the retrained reference for the primary inference.** The shipped bundle has already learned from some rows in the new confirmation partition, so comparing directly against it cannot establish held-out gain. The proposed same-fit/same-calibration classical refit is the right primary control. Keep production performance as a separately labelled regression benchmark. This experiment changes encoder size, context length, state conditioning, and heads together: a gain belongs to the complete candidate recipe. It cannot identify the benefit of model size or the intent-conditioned action head individually. Such attribution needs ablations only if that stronger claim is desired.

6. **Freeze one primary contrast before confirmation.** Predeclare the selected ensemble against the matched classical reference, the action gain rule, and whether the intent margin is a point-estimate guard or statistical noninferiority. A point difference above -1 point is a guard, not proof of noninferiority. Report paired conversation-bootstrap intervals for intent as well as action, review share, action-only cost, and forbidden-automatic rate. Sample conversations with replacement and retain every row in each sampled conversation; estimate the row-weighted metric consistently. If the selected mix is zero, the experiment selected the reference and provides no neural gain. Do not choose among standalone neural, ensemble, and later API candidates after seeing their confirmation scores. Additional candidates evaluated there are exploratory unless their family and comparison rule were fixed beforehand.

7. **Preserve the remaining validity boundaries.** Save the four group memberships and assert unique row IDs, full coverage, and pairwise-disjoint conversations. Derive all fit-dependent objects from fit rows. Previously developed text/state rules and the repeatedly studied public corpus remain prior research exposure; new seeds do not erase it. Public dev/noisy/hostile checks are regression diagnostics. Use the official grader for its exact top-70 tie behavior and all development bars, including intent macro-F1. Threshold tuning requires identical high/low-risk cost assumptions on both systems; report review burden alongside automatic accuracy.

A later bounded API experiment should use the same rows for each model, fit-only retrieval, a rule fixed before outcome inspection for choosing any budget-limited cohort, and recorded failures as fallbacks rather than dropped cases. A low-confidence cohort measures that cohort's gain; it does not by itself estimate all-request action accuracy. A neural confirmation result does not establish any API result.

Reproducibility needs the actual checkpoint, tokenizer/revision, label order, preprocessing and truncation rules, training settings/seed, selected checkpoint, temperatures, blend weight, and correctness/routing artifacts. Persist those outputs as they are produced. An absent decorative hash or receipt is no reason to restart correct work. Production adoption additionally needs real integration, the stated regression tests and matched latency measurements on an available machine; CPU benchmark results and a busy GPU do not establish deployable throughput.
